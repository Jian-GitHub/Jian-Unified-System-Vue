## 仪表盘加载策略

仪表盘按视口分别激活汇总、趋势/日历和近期记录请求；路由组件本身也使用动态导入。各区域维护独立加载与错误状态，一个接口失败不会阻塞其余区域。月份、筛选和税率变化只刷新已经激活的相关区域，尚未进入视口的区域在首次显示时使用最新条件。

近期记录使用后端 `next_cursor` 每次读取 8 条，滚动接近列表底部时继续追加，同时保留“加载更多”按钮作为键盘操作和无 IntersectionObserver 环境的后备入口。分页层会忽略过期响应和重复记录，拒绝后端重复游标；筛选变化会使旧请求失效并从第一页重新加载。

## 仪表盘动效

动效采用项目内的轻量 Vue 指令和组件实现，没有额外引入 Vue Bits 或 ECharts 运行时。财务数字使用保留最终值 `aria-label` 的递增过渡；摘要卡、趋势、收入构成、月历和近期记录进入视口后渐入，鼠标等精细指针可触发低对比度聚光反馈。触屏不启用指针追光，系统设置“减少动态效果”后会关闭渐入、数字递增、悬浮位移和图表动画。

趋势图继续使用现有 Chart.js，数据点以短间隔分段进入；超过 80 个数据点时自动关闭入场动画，避免大范围日期查询产生无意义的渲染成本。动画只修饰真实 API 数据的状态变化，不延迟请求，也不参与金额计算或可访问文本。

顶部工作区导航使用 Element Plus Affix 固定在窗口上方。近期记录表格最高 320px，下一页请求由表格内部滚动触发，不会因为页面底部哨兵持续可见而一次加载完所有记录；无滚动或辅助技术环境仍可使用“加载更多”按钮。

右上角直接复用 Apollo 的日夜开关与翻译图标，不附加 Apollo 登录页的面板边框或内阴影。语言菜单支持中文、英文、日文、韩文，并按 Apollo 的规则显示“目标语言自称 - 当前界面语言中的名称”。币种选择和 Apollo 入口位于账户菜单内；币种是全局记账和显示单位，切换时保留已有金额数值，不执行不可审计的隐式汇率换算，发票页面和 PDF 同步使用所选币种。Apollo 账户入口默认使用当前主机的 `20551` 端口，部署到其他来源时通过 `VITE_APOLLO_URL` 覆盖。顶部导航与侧栏使用同一套磨砂玻璃效果，桌面侧栏可收起，状态会保存在浏览器中。

在本目录执行 `npm install`、`npm run dev`。当前局域网地址为
`http://192.168.2.7:15173`；Apollo 前端为 `http://192.168.2.7:20551`。

## 认证与权限

Hephaestus 不包含登录表单，不收集密码，不接收 URL 中的账户 Token。
访问受保护页面时，浏览器进入 `/api/v1/auth/start`，由收入 API 发起 Apollo
授权。Apollo 登录、确认授权后，将一次性授权码返回
`/api/v1/auth/callback`。收入 API 使用服务端凭据和 S256 PKCE 交换会话，
设置 HttpOnly Cookie，再返回原页面（保留查询参数和锚点）。

Apollo 统一保存身份、会话、有效期及 Hephaestus 权限（scope 4）。收入 API/RPC
每次请求在线校验 Apollo；撤销授权、账户删除、账户会话版本变化后，后续请求失效。
收入记录的所有者隔离仍由收入后端依据已验证身份执行。

- 收入、保存的 Invoice 列表和发行人设置需要认证。
- Invoice PDF 制作继续免登录；游客草稿只在内存。
- 已登录 Invoice 草稿仍是按账户隔离的浏览器缓存，不是服务端私有文档库。
  独立 Invoice API 尚未实现，本次不把本地缓存宣称为云端保存或服务端权限控制。
- Hephaestus 退出撤销当前浏览器的子系统会话并回到公开 Invoice。
  Apollo 用户中心退出会使账户会话版本失效，关联 SSO 会话的后续访问均被拒绝。
- 认证服务不可用、权限拒绝、过期回跳显示状态页，可手动重试；不自动循环登录。

## 配置与构建

`vite.config.ts` 只代理 `/api` 到收入 API，默认 `http://127.0.0.1:18101`。
本地隔离验证可用服务端环境变量 `HEPHAESTUS_API_TARGET` 覆盖；该值不是身份凭据。
Apollo 授权地址、公开回跳 origin、client ID/secret 和临时状态签名密钥都在后端
`hephaestus-api/etc/hephaestus-api.yaml`，前端不需要配置登录 URL 或任何密钥。
两个后端数据库均按各自 `etc/*.yaml` 配置使用本地 3306，具体数据库准备见后端 README。

若局域网 IP 变化，手动修改后端的 `SSO.AuthorizeURL`、`SSO.PublicURL`、Apollo client
的 `RedirectURIs` 以及 Apollo API 的 `FrontendURL`。`vite.config.ts` 中的
`proxy.target` 是本机服务间通信地址，保留 `127.0.0.1` 即可，不控制浏览器跳转。

`npm run build` 先检查 Vue/TypeScript 再构建。TypeScript 配置使用 `noEmit`，
并明确加载 `vite.config.ts`，避免产生会覆盖 TS 源码解析顺序的旁置 `.js`。
不要提交 `dist`、`node_modules`、`*.tsbuildinfo` 或生成的 `vite.config.js`。

- 周历每页四周，周一至周日横排，点击日期进入当日记录。发票和导入列表对当前加载集合分页；导入列表仍受后端原有返回数量上限约束。
- 新增到账构成、星期收入分布、实际工作日和平均日税前收入；指标来自当前筛选汇总与日历数据。未知费用不视为已知报销。
- 图表支持暗色模式、减少动画偏好；快速切换筛选时忽略过时响应，普通记录税率在设置页调整，返回仪表盘时按新设置请求。

## 工作台视觉改造（2026-09-14）

采用深色侧栏、浅灰工作区与翡翠绿强调色，统一收入、记录、导入、来源、设置和发票的导航及基础控件。首页按结算情景、核心收入指标、收入趋势和构成、工作日历、最近记录组织信息；高级筛选默认收起，CSV 导出使用当前筛选与情景税率调用现有导出接口。金额、环图与图表均来自 API 汇总，无内置展示数据。

预计到账位于首张指标卡；税前与税后收入合并显示。主时薪为 `known_cash_estimate_cents ÷ (duration_minutes / 60)`，对应当前期间预计收款（含已知费用返还）除以全部工时，包括尚未确认／结算的工作；同卡次级指标显示 `net_estimate_cents ÷ (duration_minutes / 60)`，便于查看不含费用返还的税后工资时薪。两者均不使用 `confirmed_duration_minutes` 作分母。金额沿用后端汇总中已有的规则估算，前端不为缺失工资或未知费用补造预测；汇总不完整时明确标注，工时为零或数据尚未返回时显示 `—`。

趋势默认按周；月历每页四周，默认定位到当前周所在页（按奥克兰日期），筛选范围不含本周则显示第一页。页面随窗口宽度调整指标列数，并按窗口高度限制图表尺寸；较矮桌面窗口收紧页头，表格行距与卡片内边距统一压缩，宽屏使用全部可用工作区宽度。

支持明暗主题、中英文切换、移动端抽屉导航、键盘焦点和减少动画偏好。发票编辑器沿用白色文档预览，周围工作区跟随主题；表格、日历和 A4 预览在窄屏下局部滚动。

验收使用隔离浏览器中的内存 API 数据，覆盖 1440px 桌面和 390px 窄屏、页面导航、筛选展开、月份与图表粒度联动、税率刷新、CSV 导出调用、空数据、请求失败与恢复；未修改业务记录，也未验收真实 Apollo 登录及后端导出内容。该浏览器运行环境未安装中文字体，中文切换验证了文本和语言属性，中文字体外观需在具备中文字体的系统中查看。
